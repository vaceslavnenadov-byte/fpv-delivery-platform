# fpv-delivery-platform

Платформа гражданских перевозок и доставки с использованием FPV-дронов невоенного назначения:
кабинеты заказчика, оператора, наводчика (координатора), техника и администратора; сервисный
модуль дрона с симулятором; доменная аутентификация; видеоподтверждение последних 15 секунд;
баллы за качество; неизменяемый аудит; развёртывание на Debian 13 + PostgreSQL 17 через Ansible.

> Целевая ОС — **Debian 13 «trixie»** (по решению заказчика от 13.10.2026 вместо Debian 11 из ТЗ,
> у которого закончилась поддержка). Подробности — [docs/os-lifecycle.md](docs/os-lifecycle.md).

## Структура

```text
fpv-delivery-platform/
├── backend/          FastAPI (Python 3.13): fpv/{api,services,security}, миграции, воркер, CLI
├── frontend/         React 18 + TypeScript (Vite): кабинеты всех ролей
├── drone-agent/      сервисный модуль дрона: адаптер оборудования (только чтение) + симулятор
├── database/
│   ├── migrations/   SQL-миграции PostgreSQL (схема, таблица прав, правила баллов)
│   └── seeds/        демонстрационные устройства и политики доступа
├── packaging/debian/ пакеты fpv-platform и fpv-drone-agent, скрипт apt-репозитория
├── deploy/ansible/   комплект /tmp/ancible: ansible.cfg, requirements, inventory, group_vars,
│                     host_vars, playbooks, roles (11), scripts (install/run/preflight/postflight/rollback/build)
├── tests/            backend (107), ansible (40)
├── docs/             архитектура, модель данных, права, угрозы, развёртывание, безопасность
└── .env.example
```

Дополнительные пакеты и зависимости — отдельный репозиторий
[`fpv-delivery-packages`](../fpv-delivery-packages) (тег `v2026.10.1`, указан в `fpv_packages_ref`).

## Быстрый запуск стенда

См. [docs/deployment.md, раздел 9](docs/deployment.md#9-запуск-для-разработки-и-стенда-без-домена):
PostgreSQL → миграции → эмулятор каталога (`python -m fpv.cli dev-directory`) → backend → frontend →
симулятор дрона с ключом, выпущенным в кабинете заказчика.

## Критерии готовности первой версии (ТЗ, разд. 21)

| # | Критерий | Состояние | Как проверено |
|---|---|---|---|
| 1 | Вход доменным пользователем | реализовано; проверено на эмуляторе каталога и эмуляторе AD (ldap3) | тесты; реальный контроллер домена в среде отсутствовал |
| 2 | Доступ только к разрешённым устройствам, функциям, ресурсам | реализовано | `test_permissions.py`, `test_device_access_policy`, `test_shares_policy.py` |
| 3 | Подключение рабочих устройств к домену | роль `fpv_domain` (realmd/SSSD, winbind) | синтаксис и шаблоны; присоединение на реальном домене не выполнялось |
| 4 | Персональные и общие папки в ЦОД | роль `fpv_network_shares` + верификация ACL | модель доступа и генерация конфигураций — тестами; на реальном Samba не прогонялось |
| 5 | Доменные пароли не сохраняются | да | `test_domain_password_never_stored` |
| 6 | Регистрация пользователей всех ролей с привязкой к домену | да | тесты, UI-сценарий |
| 7 | Регистрация тестового дрона | да | тесты, UI-сценарий |
| 8 | Заказ А→Б | да | тесты, UI-сценарий |
| 9 | Передача на сервер и отображение оператору | да (очередь + WebSocket) | тесты, UI-сценарий |
| 10 | Назначение оператору | да | тесты, UI-сценарий |
| 11 | Выполнение с симулятором | да | `test_drone_agent.py`, UI-сценарий |
| 12 | Клип 15 с при наличии потока | да | `test_video.py` (в т.ч. реальный MPEG-TS → MP4) |
| 13 | Проверка клипа администратором | да | UI-сценарий |
| 14 | Подтверждение или отклонение | да | тесты, UI-сценарий |
| 15 | Баллы начисляются один раз | да | `test_points_awarded_once` |
| 16 | История заказа и события | да | хронология, аудит |
| 17 | Запуск в изолированном окружении Debian 13 + PostgreSQL | backend — на Python 3.13 + PostgreSQL 17; комплект — в контейнере Debian 13 без сети | частично: полный стек на чистом Debian 11 с пакетами из зеркала не прогонялся |
| 18 | Основной и пакетный репозитории с версиями и целостностью | да | `scripts/verify.sh`, `build-bundle.sh` |
| 19 | /tmp/ancible, venv, установка Ansible | да | контейнерный тест (`--network none`) |
| 20 | playbook, роли и .sh согласованы, ошибки обрабатываются | да | `test_ansible.py`, shellcheck |
| 21 | Локальный и централизованный режимы, повторный запуск без изменений | локальный — прогон в контейнере, второй запуск `changed=0`; централизованный — проверка аргументов и назначения ролей | SSH-развёртывание на реальные узлы не выполнялось |

Не реализовано в первой версии (явно): управление полётом и автономная навигация, Kerberos SSO
в браузере, e-mail/SMS-уведомления, потоковая репликация PostgreSQL, тайловая карта (используется
схема маршрута, работающая без внешних сервисов).
