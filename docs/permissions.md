# Таблица прав и доступ к устройствам

Аутентификация — доменная (служба каталогов). Авторизация — в приложении: каждый защищённый
endpoint проверяет конкретное разрешение (`Principal.require(...)`) при каждом запросе; скрытие
элементов интерфейса — только удобство. Таблица ниже сгенерирована из миграций
(`0002_reference_data.sql` и последующих, по состоянию на `0014_service_zones.sql`) (тест `test_every_permission_used_in_code_exists` проверяет, что все
разрешения, используемые в коде, существуют в каталоге).

Особые правила:

* права оператора на работу с заказами (`order.queue.read`, `order.accept`, `order.execute`, `order.report`)
  действуют только после подтверждения допуска администратором (`operators.status = approved`);
* наводчик/координатор не получает прав оператора или администратора; видит только назначенные заказы;
* заказчик не видит позицию дрона (телеметрия — только `telemetry.read_assigned` / `telemetry.read_all`);
* прямая трансляция (`video.live`) доступна только во время выполнения заказа и только тем, кто видит заказ:
  заказчику — свой, оператору и координатору — назначенный, администратору — любой; каждое открытие
  трансляции записывается в журнал аудита (`video.live.view`). Заказчик видит изображение с камеры
  по решению заказчика платформы от 15.10.2026; координаты дрона ему по-прежнему не передаются;
* чужие заказы и дроны возвращают 404 (существование объекта не раскрывается);
* сервисный модуль дрона не является пользователем: отдельный контур с ключом устройства.

## Сопоставление доменных групп

| Доменная группа | Роль приложения | Вход на узлы (SSSD `simple_allow_groups`) |
|---|---|---|
| FPV-Customers | customer | — |
| FPV-Operators | operator | рабочие станции операторов |
| FPV-Coordinators | coordinator | рабочие станции координаторов |
| FPV-Technicians | technician | рабочие станции техников, наземные станции |
| FPV-Recruiters | recruiter | — (работает через веб-клиент `/recruiter/`) |
| FPV-Admins | admin | рабочие станции администраторов |
| FPV-Linux-Admins | — | все серверы и станции, sudo |

Роли из групп пересчитываются при каждом входе и при периодической повторной проверке
(`FPV_DIRECTORY_REVALIDATE_S`, по умолчанию 300 с). Администратор может назначить роль
вручную (`source = manual`) — например, на время переходного периода; такие назначения
аудируются и видны в «Пользователи и роли».

## Устройства

`devices` + `device_access_policies`: вход с указанием кода рабочего места разрешён, только если
есть правило для роли пользователя или его доменной группы. Демонстрационные устройства —
`database/seeds/dev_devices.sql`. На уровне ОС доступ к узлам ограничивается тем же списком
групп (`fpv_login_groups` в `group_vars/*_workstations.yml` → SSSD и `AllowGroups` в sshd).

## Сетевые ресурсы

Права на файловые ресурсы отделены от прикладных ролей, но управляются согласованно —
по тем же доменным группам. Таблица `fpv_network_shares` (`deploy/ansible/group_vars/all.yml`):

| Ресурс | Чтение и запись | Только чтение |
|---|---|---|
| fpv-operations | Operators, Coordinators | Admins |
| fpv-maintenance | Technicians | Admins, Operators |
| fpv-admin | Admins | — |
| fpv-common | Admins | Operators, Coordinators, Technicians |
| личная папка (`[homes]`) | только владелец | — |

Всё, что не разрешено явно, запрещено. Подробнее — `domain-and-storage.md`.
