# Доменная инфраструктура, учётные записи, хранение данных в ЦОД

## 1. Допущения

ТЗ не фиксирует доменную технологию и файловый протокол, поэтому приняты следующие допущения.
Конфигурация не выдаёт их за подтверждённые настройки: значения в `group_vars/all.yml` — примеры.

| Параметр | Допущение | Альтернатива |
|---|---|---|
| Служба каталогов | Active Directory или Samba AD DC, домен `fpv.local`, Kerberos realm `FPV.LOCAL` | FreeIPA: `FPV_LDAP_ATTR_OBJECT_ID=ipaUniqueID`, `FPV_LDAP_ATTR_DISABLED=nsAccountLock`, `FPV_LDAP_NESTED_GROUPS=false`, клиенты — `ipa-client-install` вместо realmd |
| Linux-узлы | realmd + adcli + SSSD + Kerberos (`fpv_domain`) | — |
| Файловые серверы | Samba (`security = ADS`) + winbind, SMB 3, шифрование обязательно | NFSv4 + Kerberos (`sec=krb5p`) |
| Рабочие станции | Debian 11 в домене, сетевые папки через pam_mount (`sec=krb5`) | Windows-станции — те же ресурсы по SMB, GPO |
| Вход в приложение | LDAPS simple bind (пароль проверяется каталогом и не сохраняется) | Kerberos SSO (SPNEGO на nginx) — следующий этап |

## 2. Учётные записи и группы

Учётные записи создаёт и блокирует сетевой администратор в службе каталогов. Приложение
**не создаёт локальных паролей** и не хранит доменные пароли: в `users` хранятся идентификатор
объекта каталога (`objectGUID`), имя, отображаемое имя, контакты.

Группы (OU `OU=FPV,OU=Groups`): `FPV-Customers`, `FPV-Operators`, `FPV-Coordinators`,
`FPV-Technicians`, `FPV-Admins` — роли приложения; `FPV-Linux-Admins` — администрирование узлов
(sudo); `FPV-Backup-Operators` — резервное копирование.

Служебные учётные записи:

* `svc-fpv-ldap` — только чтение каталога (поиск пользователей и групп) для приложения;
* `svc-domainjoin` — делегированное право присоединять компьютеры в `OU=Servers,OU=FPV`;
* `ansible-deploy` — доменная (или локальная) учётная запись автоматизации, вход по ключу SSH.

### Процедуры

| Процедура | Действия |
|---|---|
| Создание пользователя | создать учётную запись в каталоге → добавить в группу роли → пользователь входит в приложение (профиль создаётся автоматически) и заполняет контакты. Оператор дополнительно подаёт заявку на допуск; администратор приложения подтверждает. |
| Назначение/смена роли | изменить членство в группах каталога; приложение пересчитает роли при следующем входе или при повторной проверке (≤ 5 мин); узлы — через SSSD |
| Блокировка | отключить учётную запись в каталоге. Приложение отзывает сессии при повторной проверке (≤ 5 мин) или сразу — кнопкой «Синхронизировать с доменом» / `python -m fpv.cli sync-directory`; вход на узлы блокирует SSSD. Срочно только в приложении: «Отключить» в «Пользователи и роли» |
| Увольнение | блокировка в каталоге + в приложении «удалить» → обезличивание профиля; история заказов, баллы и аудит сохраняются |
| Восстановление доступа | разблокировать учётную запись в каталоге; если доступ отключал администратор приложения — включить в «Пользователи и роли»; пользователь входит заново (старые сессии не восстанавливаются) |
| Утрата пароля | сброс пароля в службе каталогов (приложение не участвует) |

Все входы, отказы, изменения ролей и прав, отзывы доступа записываются в аудит.

## 3. Хранение в ЦОД

| Данные | Место | Защита |
|---|---|---|
| БД PostgreSQL | серверы БД в ЦОД (`db_servers`) | TLS + SCRAM, доступ только из подсети приложений, резервные копии |
| Видеоподтверждения | том хранилища ЦОД (`/srv/fpv-evidence`, NFS/iSCSI) или S3 (MinIO) в ЦОД | SHA-256, файлы только для чтения / Object Lock, доступ только учётной записи службы |
| Буфер видео (spool) | локальный диск сервера приложений | права 0750 службы; рекомендуется шифрование LUKS |
| Персональные папки | файловый сервер `/srv/homes/<user>` | 0700, владелец — пользователь, создаются при первом подключении |
| Общие папки | файловый сервер `/srv/shares/*` | POSIX ACL по доменным группам (текущие и наследуемые), Samba `valid users`/`read list`/`write list` |
| Журналы | journald (persistent) + центральный сервер журналов по TLS (`fpv_syslog_remote`) | ротация, ограничение объёма |

Рабочие станции не используются как основное хранилище: сетевые папки монтируются при входе
пользователя с его билетом Kerberos и отключаются при выходе.

### Таблица прав на сетевые ресурсы

Единый источник — `fpv_network_shares` (`deploy/ansible/group_vars/all.yml`). Из неё
генерируются smb.conf, ACL каталогов и монтирования pam_mount; таблица — в `permissions.md`.
Права файловых ресурсов отделены от ролей приложения, но назначаются по тем же группам.

### Проверка прав на реальной инфраструктуре

```bash
# под пользователем группы FPV-Operators (после входа, есть билет Kerberos)
smbclient -k //fs1.dc.fpv.local/fpv-operations -c 'put /etc/hostname test.txt; rm test.txt'  # успех
smbclient -k //fs1.dc.fpv.local/fpv-maintenance -c 'put /etc/hostname test.txt'              # NT_STATUS_ACCESS_DENIED
smbclient -k //fs1.dc.fpv.local/fpv-admin -c 'ls'                                            # NT_STATUS_ACCESS_DENIED
smbclient -k //fs1.dc.fpv.local/<другой_пользователь> -c 'ls'                               # отказ
```

Автоматически: `fpv_verify` сверяет ACL каталогов с таблицей; модульные тесты
`tests/ansible/test_shares_policy.py` проверяют матрицу доступа и сгенерированные конфигурации.

## 4. Резервное копирование и восстановление

* БД: `fpv-pg-backup.timer` ежедневно — `pg_dump -Fc`, SHA-256, хранение 14 дней, **проверка
  восстановления** во временную БД с подсчётом строк. Ненулевой код — сигнал мониторингу.
* Видео и сетевые папки: снимки/репликация тома средствами системы хранения ЦОД (вне Ansible).
* Восстановление БД: `pg_restore --clean --dbname=fpv <копия>` при остановленных `fpv-api`, `fpv-worker`;
  затем `python -m fpv.cli verify-audit` и `verify-videos`.
* Мониторинг свободного места: `fpv-healthcheck` (порог `fpv_disk_free_warn_pct`), экспортер метрик узла.
