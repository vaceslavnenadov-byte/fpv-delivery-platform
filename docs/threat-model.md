# Модель угроз

Методика — STRIDE по элементам архитектуры. Активы: учётные записи и сессии, данные заказов
и получателей (персональные данные), видеоподтверждения, баллы операторов, журнал аудита,
ключи устройств, конфигурация и секреты, сетевые папки.

## Границы доверия

1. Интернет / сеть организации ↔ nginx в ЦОД (TLS).
2. nginx ↔ API (локальный адрес), API ↔ PostgreSQL (TLS + SCRAM вне узла), API ↔ служба каталогов (LDAPS).
3. Сервисный модуль дрона ↔ контур `/drone-link` (ключ устройства).
4. Рабочие станции ↔ файловый сервер (SMB3, Kerberos, шифрование).
5. Управляющий узел Ansible ↔ узлы (SSH по ключу, sudo по доменной группе).

## Угрозы и меры

| # | Угроза (STRIDE) | Мера | Где |
|---|---|---|---|
| S1 | Подбор пароля доменной учётной записи | лимит входов (приложение + nginx `limit_req`), блокировка политики AD, аудит отказов | `deps.py`, nginx, `audit` |
| S2 | Кража сессии | HttpOnly + Secure + SameSite=Strict cookie, в БД только SHA-256, тайм-аут простоя и срок жизни, отзыв при выходе/блокировке | `identity.py` |
| S3 | CSRF | двойная отправка токена + сверка с хешем в сессии для всех изменяющих запросов | `deps.current_principal` |
| S4 | Перехват WebSocket с чужого сайта | проверка `Origin` = `Host`, аутентификация по сессии, повторная проверка каждые 60 с | `realtime.py` |
| S5 | Поддельный дрон | ключ устройства (256 бит), хранится только хеш, выпускается владельцем после допуска, ротация; блокировка дрона отключает контур | `drones.py` |
| S6 | LDAP-инъекция / анонимный bind | строгий формат имени, экранирование фильтра, пустой пароль запрещён | `directory.py` |
| T1 | Подмена статуса/результата через API | строгие схемы (лишние поля → 422), переходы только автоматом, права на каждое действие | `schemas.py`, `orders.py` |
| T2 | Подмена видео | SHA-256 при захвате, запрет перезаписи объекта, файлы только для чтения / S3 Object Lock, триггер БД против изменения хеша/ключа, проверка целостности | `video.py`, `storage.py` |
| T3 | Правка журнала аудита / истории | триггеры запрета UPDATE/DELETE/TRUNCATE, хеш-цепочка с проверкой (обнаруживает правку даже суперпользователем) | миграция 0001, `audit.py` |
| T4 | Подмена установочного комплекта | SHA256SUMS комплекта и коллекций, `--require-hashes` для pip, подписанные репозитории apt | `install.sh` |
| R1 | Отказ от действия | аудит всех административных и критических действий (кто, когда, IP, до/после) | `audit.record` |
| I1 | Утечка паролей | доменные пароли не сохраняются и не логируются; секреты конфигурации — файлы 0640, Vault, `no_log` | тест `test_domain_password_never_stored` |
| I2 | Раскрытие чужих данных | 404 для чужих заказов/дронов; позиция дрона только при праве на телеметрию; видео — только `video.read` | `orders.visible_order` |
| I3 | Утечка через журналы | маскирование ключей `password/token/secret/...` в деталях аудита | `audit._scrub` |
| D1 | Перегрузка API / контура дрона | лимиты запросов, ограничение размера сегментов и пакетов телеметрии, `client_max_body_size` | `deps.py`, nginx |
| D2 | Недоступность службы каталогов | новые входы — 503 с аудитом; активные сессии продолжают работать до повторной проверки | `identity.authenticate_session` |
| D3 | Сбой хранилища видео | клип остаётся в spool, загрузка повторяется (до 10 попыток), затем статус dead и сигнал мониторинга | `events.py` |
| E1 | Повышение прав роли | права — из таблицы прав в БД; оператор без допуска не получает прав на заказы; координатор не имеет прав оператора | `identity.build_principal` |
| E2 | Отозванный сотрудник сохраняет доступ | повторная проверка учётной записи в каталоге, плановая синхронизация, отзыв всех сессий; доступ к узлам — SSSD (`ad_gpo_access_control`) | `identity.py`, роль `fpv_domain` |
| E3 | Команды полёта через API | в API и адаптере нет команд управления; контур дрона только принимает данные | `drone_link.py`, `adapters/base.py` |

## Остаточные риски (принимаются в v1 или требуют мер организации)

* Debian 11, PostgreSQL 13, Python 3.9 вне стандартной поддержки — см. `debian11-lifecycle.md`.
* Ограничение частоты в процессе приложения не разделяется между процессами — основной барьер на nginx.
* Сессия, у которой открыт WebSocket, не истекает по простою (продлевается проверкой раз в 60 с).
* Кольцевой буфер видео хранится на диске узла API до загрузки — диск должен быть зашифрован
  средствами ЦОД (LUKS) и доступен только учётной записи службы.
* Достоверность видео ограничена достоверностью источника: подпись видеопотока на борту — этап интеграции оборудования.
* SSO по Kerberos (SPNEGO) в браузере не реализован: вход по доменному паролю через LDAPS.
