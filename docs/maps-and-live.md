# Карты-подложки и прямая видеотрансляция

## 1. Карты-подложки

На схеме маршрута (карточка заказа, новый заказ) под точками А и Б, маршрутом и треком дрона
показывается карта района работ. Карты загружает администратор; внешние картографические
сервисы не используются, поэтому всё работает в изолированной сети ЦОД.

### Загрузка (администратор → «Карты»)

1. Подготовьте изображение района: PNG, JPEG или WebP, до 50 МБ и до 20 000 пикселей по стороне.
   Это может быть экспорт из ГИС (QGIS: «Проект → Импорт/экспорт → Экспорт карты в изображение»),
   скан бумажной карты или снимок. Изображение должно быть ориентировано на север.
2. Определите координаты краёв изображения в градусах WGS 84:
   **север** — широта верхнего края, **юг** — нижнего, **запад** — долгота левого края,
   **восток** — правого. В QGIS их показывает экспорт (экстент); на бумажной карте — по рамке.
3. Укажите название, описание (источник, дата) и границы, нажмите «Загрузить».

Ограничения: юг < север, запад < восток; область не больше 5° по широте и 10° по долготе
(подложка рассчитана на район работ — при большем охвате искажения проекции заметны).

### Выбор карты для маршрута

Для каждого маршрута выбирается включённая карта, в которую попадает больше всего точек
маршрута (А, Б, контрольные точки); при равенстве — самая подробная (меньшая по площади).
Если подходящей карты нет — показывается схема с сеткой, как раньше. Пользователь может
отключить подложку флажком «Карта: …» под схемой (настройка запоминается в браузере).

Изображение растягивается по указанным границам линейно по широте и долготе. Для района
в десятки километров отличие от проекции Web Mercator незаметно.

### Управление

«Изменить» — название и границы, «Отключить/Включить» — без удаления файла, «Удалить» — запись
и файл. Все действия записываются в журнал аудита (`map.uploaded`, `map.updated`, `map.deleted`).

### Безопасность

* Тип файла определяется по содержимому (сигнатуре), а не по расширению. SVG и другие форматы
  с активным содержимым не принимаются.
* Файлы хранятся в объектном хранилище платформы (`maps/<id>.<ext>`) с контрольной суммой SHA-256.
* Изображение выдаётся только аутентифицированным пользователям с разрешением `map.read`,
  с заголовками `X-Content-Type-Options: nosniff` и `Content-Security-Policy: default-src 'none'`.
* Ограничение размера — на nginx (`client_max_body_size 60m` для `/api/v1/admin/maps`) и в приложении
  (`FPV_MAP_MAX_BYTES`, по умолчанию 50 МБ).

### API

| Метод | Путь | Разрешение |
|---|---|---|
| GET | `/api/v1/maps` (`?all=true` — с отключёнными, только `map.manage`) | `map.read` |
| GET | `/api/v1/maps/{id}/image` | `map.read` |
| POST | `/api/v1/admin/maps?name=&north=&south=&west=&east=&description=` — тело: файл | `map.manage` |
| PATCH | `/api/v1/admin/maps/{id}` — `{name, description, active, north, south, west, east}` | `map.manage` |
| DELETE | `/api/v1/admin/maps/{id}` | `map.manage` |

## 2. Прямая видеотрансляция

Во время выполнения заказа (статус «Выполняется») в карточке заказа есть блок
«Прямая трансляция». Кнопка «Смотреть трансляцию» открывает видео с камеры дрона.

### Кто видит

| Роль | Доступ |
|---|---|
| Заказчик | свой заказ |
| Оператор | назначенный заказ |
| Координатор | назначенный заказ |
| Администратор | любой заказ |
| Техник | нет |

Каждое открытие трансляции записывается в журнал аудита (`video.live.view`). Чужие заказы
возвращают 404. После завершения заказа трансляция недоступна; остаётся видеоподтверждение
(последние 15 секунд).

### Режимы

| Режим | Как работает | Когда использовать |
|---|---|---|
| **Видео** | HLS: поток H.264, плеер hls.js (в Safari — встроенный), задержка 3–6 с | по умолчанию |
| **Кадры** | последний кадр (JPEG) раз в секунду | браузер без H.264, медленный канал |

Если браузер не воспроизводит H.264, интерфейс сам включает режим «Кадры». Firefox ESR в
Debian воспроизводит H.264 через системные библиотеки `libavcodec` (устанавливаются вместе с
`ffmpeg`); Chrome, Яндекс Браузер, Edge и Safari — встроенными средствами. Сборки Chromium без
проприетарных кодеков H.264 не воспроизводят — для них работает режим «Кадры».

### Как устроено

```
дрон ──MPEG-TS сегменты (1 с)──► /drone-link/v1/video/segments ──► кольцевой буфер заказа
                                                                       │ (доказательная база,
                                                                       │  не изменяется)
                                                                       ▼
браузер ◄── playlist.m3u8 + <сегмент>.ts (H.264) ◄── перекодирование ffmpeg (по запросу, кешируется)
браузер ◄── frame.jpg                             ◄── первый кадр последнего сегмента
```

* Источник трансляции — тот же кольцевой буфер, что и для видеоподтверждения: отдельного
  канала от дрона не требуется, сервисный модуль дрона не меняется.
* Каждый сегмент один раз перекодируется в H.264 (`libx264`, `veryfast`, `zerolatency`) и
  сохраняется рядом в `<буфер>/live/`; копии удаляются вместе с буфером. Исходные сегменты
  и видеоподтверждение не изменяются.
* Список воспроизведения — скользящее окно из последних `FPV_LIVE_WINDOW_SEGMENTS` (по умолчанию 4)
  сегментов. Номера HLS назначает сервер, поэтому перезапуск модуля дрона (его нумерация
  начинается заново) не ломает воспроизведение; разрыв потока помечается `EXT-X-DISCONTINUITY`,
  плеер продолжает после восстановления связи.
* Требуется `ffmpeg` на сервере приложений (зависимость `Recommends` пакета, ставится ролью
  Ansible `fpv_application`). Без него — ответ 503 «Трансляция недоступна».
* nginx: в `Content-Security-Policy` добавлено `media-src 'self' blob:` (воспроизведение через
  MediaSource).

### API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/orders/{id}/live` | открыть трансляцию (проверка доступа, запись в аудит) |
| GET | `/api/v1/orders/{id}/live/playlist.m3u8` | список воспроизведения HLS |
| GET | `/api/v1/orders/{id}/live/<сегмент>.ts` | сегмент H.264 |
| GET | `/api/v1/orders/{id}/live/frame.jpg` | последний кадр |

Коды ошибок: `live_not_active` (409, заказ не выполняется), `live_no_video` (404, поток ещё не
поступает или не декодируется), `live_unavailable` (503, нет ffmpeg).

### Нагрузка

Перекодирование одного сегмента длительностью 1 с (30 кадров/с, замер на 4 ядрах): 320×240 — около
0,1 с, 1280×720 — около 0,3 с, 1920×1080 — около 0,5 с процессорного времени. Каждый сегмент перекодируется один раз независимо от числа зрителей.
Для многих одновременных трансляций высокого разрешения — выделенный узел или аппаратное
кодирование (см. `hardware-integration-plan.md`).

### Проверка

```bash
# сквозная проверка HLS внешним плеером (сессия заказчика в cookie)
ffmpeg -headers "Cookie: fpv_session=<сессия>"$'\r\n' \
  -i https://fpv.dc.fpv.local/api/v1/orders/<id>/live/playlist.m3u8 -t 10 -c copy out.ts
```
