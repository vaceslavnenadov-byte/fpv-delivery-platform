# Карты, онлайн-карты и прямая видеотрансляция

## 1. Карты-подложки

На схеме маршрута (карточка заказа, новый заказ, монитор полёта) под точками маршрута и треком
дрона показывается карта. Источников два:

* **карты района** — изображения, которые загружает администратор; работают без интернета,
  в изолированной сети ЦОД (этот раздел);
* **онлайн-карты по API-ключу** — ESRI, Google, Яндекс, 2ГИС, OpenStreetMap или любой XYZ-сервис
  (раздел 1а); серверу платформы нужен доступ к сервису карт.

### Загрузка (администратор → «Карты»)

1. Подготовьте изображение района: PNG, JPEG или WebP, до 50 МБ и до 20 000 пикселей по стороне.
   Это может быть экспорт из ГИС (QGIS: «Проект → Импорт/экспорт → Экспорт карты в изображение»),
   скан бумажной карты или снимок. Изображение должно быть ориентировано на север.
2. Определите координаты краёв изображения в градусах WGS 84:
   **север** — широта верхнего края, **юг** — нижнего, **запад** — долгота левого края,
   **восток** — правого. В QGIS их показывает экспорт (экстент); на бумажной карте — по рамке.
3. Укажите название, описание (источник, дата) и границы, нажмите «Загрузить».

Ограничения: юг < север, запад < восток; область не больше 5° по широте и 10° по долготе
(подложка рассчитана на район работ — при большем охвате искажения проекции заметны).

### Выбор карты для маршрута

Для каждого маршрута выбирается включённая карта, в которую попадает больше всего точек
маршрута (А, Б, контрольные точки); при равенстве — самая подробная (меньшая по площади).
Если подходящей карты нет — показывается схема с сеткой, как раньше. Пользователь может
отключить подложку флажком «Карта: …» под схемой (настройка запоминается в браузере).

Изображение растягивается по указанным границам линейно по широте и долготе. Для района
в десятки километров отличие от проекции Web Mercator незаметно.

### Управление

«Изменить» — название и границы, «Отключить/Включить» — без удаления файла, «Удалить» — запись
и файл. Все действия записываются в журнал аудита (`map.uploaded`, `map.updated`, `map.deleted`).

### Безопасность

* Тип файла определяется по содержимому (сигнатуре), а не по расширению. SVG и другие форматы
  с активным содержимым не принимаются.
* Файлы хранятся в объектном хранилище платформы (`maps/<id>.<ext>`) с контрольной суммой SHA-256.
* Изображение выдаётся только аутентифицированным пользователям с разрешением `map.read`,
  с заголовками `X-Content-Type-Options: nosniff` и `Content-Security-Policy: default-src 'none'`.
* Ограничение размера — на nginx (`client_max_body_size 60m` для `/api/v1/admin/maps`) и в приложении
  (`FPV_MAP_MAX_BYTES`, по умолчанию 50 МБ).

### API

| Метод | Путь | Разрешение |
|---|---|---|
| GET | `/api/v1/maps` (`?all=true` — с отключёнными, только `map.manage`) | `map.read` |
| GET | `/api/v1/maps/{id}/image` | `map.read` |
| POST | `/api/v1/admin/maps?name=&north=&south=&west=&east=&description=` — тело: файл | `map.manage` |
| PATCH | `/api/v1/admin/maps/{id}` — `{name, description, active, north, south, west, east}` | `map.manage` |
| DELETE | `/api/v1/admin/maps/{id}` | `map.manage` |

## 1а. Онлайн-карты по API-ключу

**admin** → «Карты» → «Онлайн-карты по API-ключу» → сервис, ключ → «Подключить карту» →
**«Проверить»** (сервер запрашивает одну плитку в центре зоны обслуживания и показывает результат
или ошибку сервиса). Карту можно отключить, удалить, заменить ключ, задать порядок в списке.

| Сервис | Что нужно | Проекция |
|---|---|---|
| ESRI — спутник / улицы / топография | ключ ArcGIS Location Platform (developers.arcgis.com) с доступом к Basemap styles | EPSG:3857 |
| Google — схема / спутник | ключ Google Cloud с включённым **Map Tiles API**; сеанс плиток создаётся автоматически | EPSG:3857 |
| Яндекс — схема | ключ **Tiles API** (кабинет разработчика Яндекса) | **EPSG:3395** |
| 2ГИС — схема | растровые плитки; адрес и ключ по договору с 2ГИС можно указать в шаблоне | EPSG:3857 |
| OpenStreetMap | без ключа, только для небольшой нагрузки (правила tile.openstreetmap.org) | EPSG:3857 |
| Свой сервис (XYZ) | https-шаблон с `{z}`, `{x}`, `{y}`, при необходимости `{key}` и `{s}` (поддомен): MapTiler, Mapbox Raster, HERE, Thunderforest, свой сервер плиток | 3857 или 3395 |

**Кто какую карту видит.** Заказчик выбирает карту в форме нового заказа (список «Карта» под
картой маршрута) и ставит на ней точки; выбор сохраняется в заказе (`orders.map_provider_id`).
Оператор, координатор, техник и администратор по умолчанию видят **ту же карту** — в списке
«Карта» она помечена «выбрана заказчиком»; каждый может переключиться на другую онлайн-карту,
карту района или схему — выбор запоминается в его браузере для этого заказа. Точки маршрута —
координаты, линия маршрута проводится через них по порядку; от выбора карты маршрут не зависит.

**Как устроено и безопасность.**

* Браузер получает плитки только с сервера платформы: `GET /api/v1/map-providers/{id}/tiles/{z}/{x}/{y}`
  (разрешение `map.read`). Ключ хранится в БД и клиентам не отдаётся (в списке администратора —
  только последние 4 символа); политика безопасности сайта не меняется (`img-src 'self'`).
* Ограничение — `FPV_MAP_TILE_RATE_PER_MIN` плиток в минуту на пользователя (по умолчанию 900),
  чтобы ключ нельзя было использовать для выгрузки карт. Плитки хранятся только в памяти процесса
  до 10 минут (`FPV_MAP_TILE_CACHE_ITEMS`, по умолчанию 4000) — долговременное хранение
  запрещено условиями большинства сервисов. Кеш и лимит — на каждый процесс API отдельно.
* Сервер обращается только по https, без перенаправлений, принимает в ответ только PNG/JPEG/WebP
  до 2 МБ и не обращается к адресам внутренней сети. Свой сервер плиток в локальной сети —
  `FPV_MAP_TILE_ALLOW_PRIVATE=true` в `/etc/fpv/fpv.env`.
* Доступ в интернет через прокси: `HTTPS_PROXY=http://proxy.example:3128` (и при необходимости
  `NO_PROXY=localhost,127.0.0.1,.fpv.local`) в `/etc/fpv/fpv.env`, затем `systemctl restart fpv-api`.
  Корпоративный УЦ прокси добавляется в системное хранилище (`update-ca-certificates`).
* Ошибки сервиса (неверный ключ, лимит, недоступность) показываются администратору в таблице
  онлайн-карт; пользователи в это время видят схему без подложки под плитками.
* Подключение, изменение (ключ — как `***`) и удаление онлайн-карт записываются в журнал аудита.
* Условия использования сервиса (лицензия, лимиты, указание авторства) определяет договор вашей
  организации с ним; авторство показывается на карте.

API администратора (`map.manage`): `GET/POST /api/v1/admin/map-providers` (список и готовые
настройки сервисов), `PATCH/DELETE /api/v1/admin/map-providers/{id}`,
`POST /api/v1/admin/map-providers/{id}/test`. Пользователям: `GET /api/v1/map-providers`.
Заказ: поле `map_provider_id` в `POST /api/v1/orders`. Тесты: `tests/backend/test_map_providers.py`,
`frontend/src/tiles.test.ts` (проекции EPSG:3857/3395, подбор масштаба, покрытие плитками).

## 2. Прямая видеотрансляция

Во время выполнения заказа (статус «Выполняется») в карточке заказа есть блок
«Прямая трансляция». Кнопка «Смотреть трансляцию» открывает видео с камеры дрона.

### Кто видит

| Роль | Доступ |
|---|---|
| Заказчик | свой заказ |
| Оператор | назначенный заказ |
| Координатор | назначенный заказ |
| Администратор | любой заказ |
| Техник | нет |

Каждое открытие трансляции записывается в журнал аудита (`video.live.view`). Чужие заказы
возвращают 404. После завершения заказа трансляция недоступна; остаётся видеоподтверждение
(последние 15 секунд).

### Режимы

| Режим | Как работает | Когда использовать |
|---|---|---|
| **Видео** | HLS: поток H.264, плеер hls.js (в Safari — встроенный), задержка 3–6 с | по умолчанию |
| **Кадры** | последний кадр (JPEG) раз в секунду | браузер без H.264, медленный канал |

Если браузер не воспроизводит H.264, интерфейс сам включает режим «Кадры». Firefox ESR в
Debian воспроизводит H.264 через системные библиотеки `libavcodec` (устанавливаются вместе с
`ffmpeg`); Chrome, Яндекс Браузер, Edge и Safari — встроенными средствами. Сборки Chromium без
проприетарных кодеков H.264 не воспроизводят — для них работает режим «Кадры».

### Как устроено

```
дрон ──MPEG-TS сегменты (1 с)──► /drone-link/v1/video/segments ──► кольцевой буфер заказа
                                                                       │ (доказательная база,
                                                                       │  не изменяется)
                                                                       ▼
браузер ◄── playlist.m3u8 + <сегмент>.ts (H.264) ◄── перекодирование ffmpeg (по запросу, кешируется)
браузер ◄── frame.jpg                             ◄── первый кадр последнего сегмента
```

* Источник трансляции — тот же кольцевой буфер, что и для видеоподтверждения: отдельного
  канала от дрона не требуется, сервисный модуль дрона не меняется.
* Каждый сегмент один раз перекодируется в H.264 (`libx264`, `veryfast`, `zerolatency`) и
  сохраняется рядом в `<буфер>/live/`; копии удаляются вместе с буфером. Исходные сегменты
  и видеоподтверждение не изменяются.
* Список воспроизведения — скользящее окно из последних `FPV_LIVE_WINDOW_SEGMENTS` (по умолчанию 4)
  сегментов. Номера HLS назначает сервер, поэтому перезапуск модуля дрона (его нумерация
  начинается заново) не ломает воспроизведение; разрыв потока помечается `EXT-X-DISCONTINUITY`,
  плеер продолжает после восстановления связи.
* Требуется `ffmpeg` на сервере приложений (зависимость `Recommends` пакета, ставится ролью
  Ansible `fpv_application`). Без него — ответ 503 «Трансляция недоступна».
* nginx: в `Content-Security-Policy` добавлено `media-src 'self' blob:` (воспроизведение через
  MediaSource).

### API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/orders/{id}/live` | открыть трансляцию (проверка доступа, запись в аудит) |
| GET | `/api/v1/orders/{id}/live/playlist.m3u8` | список воспроизведения HLS |
| GET | `/api/v1/orders/{id}/live/<сегмент>.ts` | сегмент H.264 |
| GET | `/api/v1/orders/{id}/live/frame.jpg` | последний кадр |

Коды ошибок: `live_not_active` (409, заказ не выполняется), `live_no_video` (404, поток ещё не
поступает или не декодируется), `live_unavailable` (503, нет ffmpeg).

### Нагрузка

Перекодирование одного сегмента длительностью 1 с (30 кадров/с, замер на 4 ядрах): 320×240 — около
0,1 с, 1280×720 — около 0,3 с, 1920×1080 — около 0,5 с процессорного времени. Каждый сегмент перекодируется один раз независимо от числа зрителей.
Для многих одновременных трансляций высокого разрешения — выделенный узел или аппаратное
кодирование (см. `hardware-integration-plan.md`).

### Проверка

```bash
# сквозная проверка HLS внешним плеером (сессия заказчика в cookie)
ffmpeg -headers "Cookie: fpv_session=<сессия>"$'\r\n' \
  -i https://fpv.dc.fpv.local/api/v1/orders/<id>/live/playlist.m3u8 -t 10 -c copy out.ts
```

Тесты: `tests/backend/test_maps_live.py`.

## 3. Трансляция с камеры заказчика

Заказчик может включить камеру телефона или компьютера в карточке своего заказа — например,
чтобы показать оператору место приёма груза или получателя. Видео видят назначенные оператор и
координатор (в карточке заказа — блок «Камера заказчика», в мониторе полёта — вкладка
«📹 Камера заказчика» рядом с картой) и администратор.

| | |
|---|---|
| Когда доступно | от принятия заказа оператором до подтверждения доставки (статусы «Принят оператором» … «Ожидает подтверждения доставки») |
| Кто транслирует | только заказчик своего заказа (разрешение `video.publish`) |
| Кто смотрит | `video.live` в пределах доступа к заказу; техник и другие заказчики — нет |
| Браузер | Firefox, Chrome, Edge, Яндекс Браузер, Safari; нужен HTTPS (камера в браузере работает только по защищённому соединению) |
| Хранение | не хранится: на сервере кольцевой буфер последних 30 секунд; удаляется при остановке, при выходе заказа из работы и через 60 с без новых данных (фоновая задача воркера) |
| Аудит | `video.customer_stream.started`, `video.customer_stream.stopped`, просмотры — `video.live.view` (`source: customer`) |

Как устроено: браузер записывает самостоятельные фрагменты по 2 секунды (MediaRecorder, WebM/VP8,
в Safari — MP4) и отправляет их `POST /api/v1/orders/{id}/customer-stream/segments` (сессия и CSRF,
заголовки `X-Segment-Seq`, `X-Segment-Duration-Ms`). Сервер проверяет тип контейнера по сигнатуре,
размер и длительность и кладёт фрагмент в отдельный буфер заказа (`<spool>/<заказ>/customer/ring`).
Дальше — тот же конвейер, что для камеры дрона: H.264 по запросу, HLS (`/live/customer/playlist.m3u8`)
или кадры (`/live/customer/frame.jpg`). При медленном канале браузер пропускает фрагменты, чтобы
показывать актуальную картинку. Видео камеры дрона и видеоподтверждения не затрагиваются.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/orders/{id}/customer-stream/segments` | фрагмент видео (заказчик) |
| GET | `/api/v1/orders/{id}/customer-stream` | идёт ли трансляция |
| DELETE | `/api/v1/orders/{id}/customer-stream` | остановить и удалить буфер (заказчик) |
| POST | `/api/v1/orders/{id}/live/customer` | открыть просмотр (аудит) |
| GET | `/api/v1/orders/{id}/live/customer/playlist.m3u8`, `…/frame.jpg`, `…/<сегмент>.ts` | просмотр |

Тесты: `tests/backend/test_customer_stream.py`.
