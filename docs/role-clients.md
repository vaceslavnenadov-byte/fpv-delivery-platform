# Разделение интерфейса по ролям

Веб-интерфейс разделён на отдельные клиенты — по одному на роль. Каждый клиент собирается в
свой бандл и содержит только свои страницы; код чужих ролей в браузер пользователя не попадает.

| Адрес | Клиент | Роль (разрешение) |
|---|---|---|
| `/` | Общий вход | — (после входа — переход в свой клиент) |
| `/customer/` | Заказчик | `order.read_own` |
| `/operator/` | Оператор | `order.queue.read` |
| `/coordinator/` | Координатор | `order.note.write` |
| `/technician/` | Техник: свой парк дронов, подключение и проверка видео, подтверждение готовности к заказам (`docs/fleets.md`) | `drone.health.write` |
| `/admin/` | Администратор | `report.read` |

## Как работает вход

1. Пользователь открывает `/`, вводит доменные логин и пароль.
2. После входа платформа переводит его в клиент его роли (при нескольких ролях — по старшинству:
   администратор → оператор → координатор → техник → заказчик).
3. Если роль ещё не назначена администратором, пользователь остаётся на `/` и заполняет профиль.
4. «Выйти» в любом клиенте возвращает на общий вход `/`.
5. Если сессия истекла или человек открыл ссылку без входа (например, окно монитора полёта),
   после входа он возвращается по тому же адресу. Адрес возврата принимается только внутри
   доступного пользователю клиента — перенаправить на сторонний сайт или в чужой раздел нельзя.

## Несколько ролей

Роли могут совмещаться (несколько доменных групп или роль, выданная администратором вручную),
например заказчик, допущенный оператором. Тогда после входа открывается старший раздел, а в боковом
меню появляется блок «Другие разделы» со ссылками на остальные клиенты пользователя. Списки заказов
в каждом клиенте показывают заказы только в этой роли: в «Моих заказах» заказчика нет заказов,
которые пользователь выполняет как оператор (сервер фильтрует по параметру `GET /api/v1/orders?as=<роль>`).

Если пользователь вручную открывает чужой клиент (например, заказчик — `/admin/`), показывается
сообщение «раздел недоступен для вашей роли» и ссылка в свой клиент. Монитор полёта открывается
внутри клиента роли: `/operator/orders/<id>/monitor`, `/coordinator/...`, `/admin/...`.

## Что это даёт

* **Меньше поверхность для атаки.** Браузер заказчика не загружает код администратора или оператора.
  Например, бандл заказчика не содержит страниц управления пользователями, правил начисления баллов,
  журнала аудита и парка дронов.
* **Нет путаницы при сбоях интерфейса.** Ошибка в одной роли не выводит на экран чужие разделы.
* **Изоляция по URL.** Каждому клиенту соответствует свой путь; nginx отдаёт только его страницы.

Это дополняет, а не заменяет защиту на сервере: все права по-прежнему проверяются backend на каждом
запросе (таблица прав, см. `permissions.md`). Разделение клиентов не является самостоятельной границей
безопасности — оно уменьшает объём кода и данных, попадающих в браузер каждой роли, и исключает
случайный показ чужих разделов. Пользователь по-прежнему не может выполнить действие, на которое у него
нет разрешения, в каком бы клиенте он ни находился.

## Сборка и размещение

* Сборка (`npm run build`) создаёт `frontend/dist/` с отдельным `index.html` и бандлом на каждый клиент:
  `dist/index.html` (вход), `dist/customer/`, `dist/operator/`, `dist/coordinator/`, `dist/technician/`,
  `dist/admin/`. Общий код (React, API-клиент, авторизация, UI) — в общих чанках.
* Каталог целиком поставляется в пакете в `/usr/share/fpv-platform/frontend` (корень сайта nginx).
* nginx отдаёт каждый клиент со своим SPA-fallback (`try_files … /<роль>/index.html`); запросы к API
  (`/api/…`, `/drone-link/…`, `/health/…`) идут на backend как прежде. Конфигурация — в пакете и в роли
  Ansible `fpv_application`.

Исходный код клиентов: `frontend/src/entries/<роль>.tsx` (точка входа и маршруты), общая конфигурация —
`frontend/src/apps/config.ts`.

## Ярлыки клиентов на рабочих местах

Ярлыки создаёт команда `fpv-shortcuts` из отдельного лёгкого пакета **`fpv-desktop`** — он ставится
на рабочие места (в том числе домашние), не содержит серверной части и зависит только от `xdg-utils`.

```bash
# один раз, от root: пакет и адрес сайта для всех пользователей компьютера
apt install fpv-desktop
editor /etc/fpv-desktop.conf          # FPV_SITE_URL=https://fpv.dc.fpv.local

# каждый пользователь — от своей учётной записи:
fpv-shortcuts                         # вход и все клиенты по ролям
fpv-shortcuts operator                # только нужный клиент
fpv-shortcuts --list | --remove       # посмотреть / удалить
```

Ярлык «FPV Доставка» (общий вход) подходит любой роли: после входа он открывает раздел пользователя.
Адрес можно задать и разово: `fpv-shortcuts --url https://адрес` или переменной `FPV_SITE_URL`.
Допускается только `http(s)://имя[:порт][/путь]` — адрес записывается в файл ярлыка.
